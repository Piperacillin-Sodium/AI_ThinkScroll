# AI思卷 网页化改造规划

状态：方案设计，尚未改动现有运行代码。默认场景为本机、单用户使用；通过浏览器访问 Python 后端。

## 1. 改造目标

将现有 CustomTkinter 桌面界面改为 HTML 网页，左侧固定五个导航入口：生成大纲、生成目录、生成草稿、定稿章节、设置。右侧显示当前模块的参数、操作按钮、可编辑内容和任务反馈。

保留现有 Python 生成逻辑和小说文件格式，增加独立的接口层与任务管理层。第一阶段前后端通过 HTTP API 通信，静态网页和接口可以由同一个本地服务提供，减少启动步骤；以后可以独立部署。

## 2. 页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ AI思卷               当前小说 / 打开已有小说       当前任务状态 │
├──────────────┬───────────────────────────────────────────────┤
│ 生成大纲     │ 模块标题、用途、当前使用模型                    │
│ 生成目录     │ 本次生成参数                                  │
│ 生成草稿     │ 主要操作按钮 / 保存状态                        │
│ 定稿章节     │                                               │
│              │ 内容编辑区或设置表单                          │
│ 设置         │                                               │
│              │ 任务阶段 / 可展开日志 / 错误和重试入口          │
└──────────────┴───────────────────────────────────────────────┘
```

- 桌面侧栏约 200–220px，右侧自适应；操作栏和内容编辑区保持清晰层级。
- 顶部的小说切换与导入属于全局操作，不增加第六个主导航。
- 参数按模块展示；模型详细配置集中到设置页，生成页仅显示当前模型及前往设置入口。
- 小屏将侧栏收起或换为可换行导航，参数改为单列，主要操作保持可见。
- 切换页签保留未保存编辑与任务状态；离开小说、关闭页面时提示未保存内容。
- 首版使用纯文本编辑器，显示字数与保存状态。生成结果与人工修改内容分别保留版本，重新生成得到候选版本，由用户选择采用。
- 候选隔离覆盖全部生成类型。大纲、目录、草稿的现有函数都会直接写入文件，必须增加独立输出与断点位置，或使用任务专属工作目录；未采用结果不得改变当前大纲、目录、人物状态或续生成断点。采用时按关联产物提交并保留回滚记录。

## 3. 五个模块

### 3.1 生成大纲

用途：生成全书架构，覆盖故事主线、人物、世界观和剧情发展。对应现有 `Novel_architecture_generate()`，页面名称统一为“生成大纲”。

- 参数：主题、类型、总章节数、单章目标字数、创作要求、可选角色库。
- 按钮：生成大纲、继续上次生成、保存修改、查看历史、前往生成目录。“继续”仅在输入版本与断点一致时可用，避免复用另一套主题的中间结果。
- 内容：大纲全文，可直接编辑。首版以完整文本为准，不强制拆成多个独立字段。
- 文件：继续使用 `Novel_architecture.txt`，该流程也会生成初始 `character_state.txt`；角色库需迁移其选择和提示词拼接逻辑。
- 初始人物状态和 `partial_architecture.json` 都属于候选任务的关联产物。已有定稿章节时，采用新大纲不能直接覆盖已积累的人物状态，应另行选择重建创作记忆。
- 前置条件：已选小说且模型配置可用；已有大纲重新生成时先保留旧版本。

### 3.2 生成目录

用途：根据大纲生成全书章节蓝图，对应 `Chapter_blueprint_generate()`。

- 参数：章节总数、大纲版本、额外目录要求。
- 按钮：生成目录、继续生成、保存修改、重新解析、前往生成草稿。继续前检查章号是否连续、章节是否完整，不能仅以最大章号判断进度。
- 内容：目录全文编辑与章节列表预览。列表展示章号、标题、梗概；高级信息包括出场人物、物品、地点、伏笔和章节目标。
- 文件：继续使用 `Novel_directory.txt`，复用 `chapter_directory_parser.py`。
- 全文是首版的编辑来源，列表是解析结果，避免双向编辑造成内容冲突。解析失败时保留原文并指出问题，不丢弃内容。
- 大纲变更后标记目录“可能需要更新”，不自动重写已经完成的章节。

### 3.3 生成草稿

用途：选择章节，准备生成上下文，预览提示词，再生成正文。

- 参数：章节选择、目标字数、本章要求、出场人物、关键物品、场景地点、时间限制。
- 按钮：准备提示词、生成草稿、保存草稿、前往定稿。
- 内容区：提示词与正文两个局部视图；提示词可编辑，正文可编辑，显示字数及保存状态。
- 章节信息默认从目录带入，本次覆盖值单独记录，不悄悄修改目录原文。
- `build_chapter_prompt()` 会调用模型进行摘要、检索和场景计划，因此“准备提示词”也是后台长任务。
- `generate_chapter_draft()` 使用用户确认后的提示词生成正文。首版保留提示词编辑步骤，后续再增加跳过预览选项。
- 文件：兼容 `chapters/chapter_N.txt`；候选结果先写入版本目录，采用后才替换当前章节文件。现有函数会直接覆盖文件，实施时必须补充可指定输出位置/不自动保存的能力，再由存储层提交。
- 未生成目录时显示前置步骤入口。上一章未定稿时提示创作记忆可能缺失，允许用户按自己的流程处理。

### 3.4 定稿章节

用途：审核并保存正文，更新供后续章节使用的创作记忆。

- 参数：章节选择、当前正文版本、目标字数。
- 主按钮：定稿本章。辅助按钮：保存修改、一致性检查、扩写、查看历史。
- 局部视图：正文、检查报告、全局摘要、人物状态；原有剧情要点文件可在此查看。
- 默认定稿流程：保存已确认正文 → 更新全局摘要 → 更新人物状态 → 更新章节向量记录。
- 状态按步骤展示；摘要/人物状态已完成但向量写入失败时，显示“定稿完成，检索记忆待补建”，提供仅补建入口。
- 当前 `finalize_chapter()` 不会自动润色全文；现有 UI 在字数低于目标的 70% 时可选扩写。新页面将扩写作为独立操作，先预览结果，再决定采用。
- 一致性检查针对当前编辑器正文的明确版本快照，输入实际大纲和剧情要点，输出报告，不默认改写正文。现有 UI 仅检查磁盘文件，且部分上下文传空，服务层需补齐；独立的“AI 润色”如有需要应作为后续新增功能。
- 同一正文版本定稿应幂等；重复点击不应重复累计摘要或向量。修改早期已定稿章节时，标记后续创作记忆需要重建，并提供顺序重建任务。

### 3.5 设置

设置页使用横向分类或分组表单，仍属于一个主导航。每组有明确保存状态。

| 分组 | 内容 | 作用范围 |
| --- | --- | --- |
| 小说参数 | 主题、类型、章节数、默认字数、创作要求、保存位置、角色库 | 当前小说 |
| 模型预设 | 预设名称、接口类型、API Key、Base URL、模型名、Temperature、Max Tokens、超时；新增/复制/删除/测试连接 | 全局 |
| 任务模型 | 大纲、目录、提示词与草稿、定稿记忆更新、一致性检查分别选择预设 | 首版沿用全局配置 |
| 检索与知识库 | Embedding 预设、地址、密钥、模型、检索条数；上传知识文件、导入进度、重建索引 | 预设全局，资料和索引归小说 |
| 网络与备份 | 代理开关、地址和端口；WebDAV 地址、账号、密码、连接测试、配置备份和恢复 | 全局 |
| 界面偏好 | 语言、主题、编辑区字号 | 用户本地偏好 |

任务模型映射沿用 `choose_configs` 中的 `architecture_llm`、`chapter_outline_llm`、`prompt_draft_llm`、`final_chapter_llm`、`consistency_review_llm`，避免迁移时改变用户原有配置意图。

预设重命名时同步更新任务引用；删除正在被任务引用的预设时要求先选择替代预设。角色资料统一用角色 ID 列表传给服务，避免照搬单章与批量流程中不同的文本拼接规则。清理向量库需明确范围，完成后将检索记忆标记为待重建。

模型密钥保存在后端；读取配置只返回掩码和是否已设置。密钥字段留空代表保持原值，删除密钥使用明确动作。普通设置导出默认隐藏密钥；包含密钥的备份由用户明确选择。现有 WebDAV 功能只备份配置文件，页面须标明备份范围。

浏览器不能像桌面程序一样直接选择任意后端目录：本机版通过后端登记小说目录，再用小说 ID 操作；知识文件通过上传接口导入。

## 4. 前后端分工与目录

建议技术组合：HTML + CSS + JavaScript 模块，Python + FastAPI，HTTP JSON 接口 + SSE 任务事件。本规划无需先引入前端构建工具。

```text
AI_NovelGenerator/
├── frontend/
│   ├── index.html
│   ├── css/app.css
│   └── js/
│       ├── app.js                # 导航与页面初始化
│       ├── api.js                # 统一接口请求、错误和事件订阅
│       ├── store.js              # 当前小说、编辑草稿、任务状态
│       └── views/                # 五个模块的页面逻辑
├── backend/
│   ├── app.py                    # HTTP 服务入口
│   ├── api/                      # 小说、文档、生成、设置、任务接口
│   ├── schemas/                  # 参数验证与响应结构
│   ├── services/                 # 生成流程、配置、知识库、备份编排
│   ├── tasks/                    # 队列、事件、停止请求、任务恢复识别
│   └── repositories/             # 文件读写、历史版本、元数据
├── novel_generator/              # 复用并逐步补充事件/停止回调
├── llm_adapters.py
├── embedding_adapters.py
├── config_manager.py
├── ui/                           # 迁移期继续保留桌面入口
└── main.py
```

前端负责导航、表单、编辑和反馈。后端负责参数校验、配置和密钥、模型调用、文件、知识库及任务执行。现有 `ui/generation_handlers.py` 中的流程编排需要迁入服务层；Tk 的变量、弹窗、`master.after()` 和控件更新不能进入 Web 后端。

核心函数虽然不直接依赖窗口，仍存在配置模块的进程级语言开关、日志、网络代理和导入路径等全局状态，需逐步显式传参。首版采用单个生成任务执行器，先确保多页签操作不会并行改写共享文件。

## 5. 接口草案

以下是建议契约，不是已实现接口。所有生成请求都只返回任务 ID，结果通过任务查询或事件订阅取得。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET / POST | `/api/projects` | 列出或创建小说 |
| POST | `/api/projects/import` | 登记已有小说目录 |
| GET / PATCH | `/api/projects/{id}` | 读取或更新小说参数 |
| GET / PUT | `/api/projects/{id}/documents/{kind}` | 大纲、目录、摘要、人物状态读写 |
| GET | `/api/projects/{id}/chapters` | 章节列表、状态、字数 |
| GET / PUT | `/api/projects/{id}/chapters/{n}` | 正文读取、带版本保存 |
| POST | `/api/projects/{id}/jobs` | 启动大纲、目录、提示词、草稿、检查、扩写、定稿等任务 |
| GET | `/api/jobs/{job_id}` | 状态、阶段、结果引用、可重试步骤 |
| GET | `/api/jobs/{job_id}/events` | SSE 日志、阶段和完成事件 |
| POST | `/api/jobs/{job_id}/cancel` | 请求停止后续步骤 |
| GET / PATCH | `/api/settings` | 脱敏读取及按字段更新设置 |
| POST | `/api/settings/test` | 测试指定模型或 Embedding 预设 |
| POST | `/api/projects/{id}/knowledge` | 上传并登记知识导入任务 |
| POST | `/api/settings/backups` | 创建配置备份任务 |
| POST | `/api/settings/backups/restore` | 恢复已选择的配置备份 |

例如任务请求包含 `type`、`chapter_number`、输入版本和本次参数；后端记录配置快照引用，不将密钥写入事件。保存请求带 `revision`，版本冲突时返回冲突信息，不覆盖另一页签的新编辑。相同请求标识重复提交返回同一个任务。

## 6. 长任务与数据一致性

- 点击生成后即返回任务 ID，后台执行，前端显示真实阶段与耗时；首版采用阶段进度，不编造模型生成百分比。
- SSE 推送阶段、日志、结果引用；刷新页面重新查询任务并按事件序号补读。切换页签或断开浏览器不终止任务。
- 当前适配器以整次调用返回结果为主。首版可以先实时显示任务阶段，调用完成后更新正文；逐字流式输出需要另行改造适配器，不应承诺换用 SSE 即自动获得。
- 任务状态区分排队、运行、停止请求中、已停止、成功、失败、中断；分步骤结果另存，允许部分完成和针对失败步骤重试。
- 停止采用检查点机制。正在等待模型的请求可能需要等待返回或超时；不将“已发出停止请求”显示为“已停止”。定稿提交阶段保持完整，避免取消造成半套记忆。
- 首版单个生成执行器串行执行，小说保存、导入、定稿和索引维护也必须走相同的资源锁。任务启动时冻结输入与设置，后续保存产生新版本。
- 采用 SQLite 保存小说登记、文档版本、任务、事件和定稿记录；正文仍用原有 TXT，备份在小说目录的 `.history/`。不将小说内容全量迁入数据库。
- 保存采用临时文件和原子替换。定稿先准备新摘要/人物状态，再提交文件并记录每步完成情况；单个文件原子替换不等于多文件事务，须有备份和恢复记录。
- 向量数据增加小说、章号、正文版本和稳定分块 ID。定稿时替换该章旧索引，而非无限追加；知识库导入也要记录来源和版本。
- 服务重启后将未完成任务标记为中断并允许重新发起；只有已实现检查点的阶段才提供恢复，不声称能从任意模型响应中间继续。
- 后端按小说 ID 解析已登记路径，文档种类使用白名单。首版默认监听本机；远程多用户部署、权限隔离与独立任务工作进程属于扩展范围。

## 7. 实施顺序与完成标准

| 阶段 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 一：界面原型 | 五页导航、公共布局、表单、编辑区、示例状态 | 能评审布局；各页状态切换清楚 |
| 二：文件与配置 | 小说登记/导入、旧配置迁移、文本读写、历史版本 | 现有小说可打开、编辑、保存；密钥不会回传 |
| 三：生成流程 | 后端服务封装、大纲/目录/提示词/草稿任务、SSE | 从设置到草稿跑通；刷新仍能找到任务 |
| 四：定稿闭环 | 审校、扩写、定稿、记忆更新与失败补建 | 人工修改被定稿采用；重复定稿不重复累计 |
| 五：补齐与验收 | 知识库、角色库、WebDAV、响应式、一键启动说明 | 原有必要功能有入口，旧文件保持可用 |

首个可用版本优先完成“配置 → 大纲 → 目录 → 提示词 → 草稿 → 编辑 → 定稿”的单章闭环。批量章节生成、逐字输出、复杂富文本、多人协作和云端部署放到后续迭代。

验收重点：使用模拟模型验证异步任务、刷新恢复、重复提交、输入版本冲突、定稿部分失败和重试；再在用户配置的模型上验证一章完整流程，避免用大量真实生成作为测试。检查缺少大纲/目录、模型超时、目录解析失败、低字数和索引失败时页面是否能给出可执行的下一步。

## 8. 现有代码依据与技术参考

- `main.py`：现有桌面程序入口。
- `ui/main_window.py`、`ui/config_tab.py`、`ui/novel_params_tab.py`：模型、任务选择、小说参数和页面状态。
- `ui/generation_handlers.py`：生成编排、提示词编辑弹窗、定稿前可选扩写、审校与批量生成。
- `novel_generator/architecture.py`、`blueprint.py`、`chapter.py`：大纲、目录、提示词和正文生成。
- `novel_generator/finalization.py`：摘要、人物状态更新和向量入库；扩写为独立函数。
- `novel_generator/vectorstore_utils.py`：当前章节向量追加逻辑，需补充版本与幂等能力。
- `ui/other_settings.py`：代理外的其他设置及 WebDAV 配置备份。
- [FastAPI 后台任务说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)：接口响应后执行任务的基础能力；本项目的任务状态、持久化和恢复须另行实现。
- [MDN：使用 Server-sent events](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)：服务器向网页发送事件及浏览器订阅机制。
